1.1.0 — 2026-10-03

Added

  • The accessibility audit now sees inside shadow roots. querySelectorAll stops at a shadow boundary, so a page built from web components was scanned as though it were nearly empty — a silent hole in a paid feature. Elements, text and labels inside open shadow roots are now audited, with aria-labelledby resolved against the root that declares the id rather than the document.
  • Keyboard access is asserted, not assumed. The same self-check now tabs through the panel in each of its tabs and through the dock layered over a page, verifying that every rendered control is reachable, that each shows a focus indicator which actually differs from its resting state, and that the dock does not swallow the page's own tab order. A negative control — a button that suppresses its own focus style — runs first, so a check that could never fail would be caught before its passes are believed.
  • Loupe is audited by its own audit. pnpm a11y:self points the same rules at Loupe's panel (both surfaces, both themes) and its dock, and fails CI on any error. It is the same code the product runs, not a copy — a harness that reimplements the rules only proves it agrees with itself.
  • Edit an element's style from the panel. Element → Style: padding, margin and gap; font family, size, line-height, weight and tracking; text and background colour; border width, style and colour; and corner radius — all applied to the live page. Numbers can be typed, arrowed (Shift ×10) or dragged, which is the Figma habit and the reason to do this on the page rather than in an editor. Per-side rows are linked by default and unlink for a single side. Every change is a Nudge adjustment: one ⌘Z per interaction, listed in Checks → Nudges, exported with the rest of the change list, and gone on reload. The first edit turns Nudge on by itself.
  • A restyle applies to the whole Shift+click group. Pick several cards, change the radius once, and all of them take it — in one undo step, the same property the group drag buys. "Give all of these the same corner" is the reason to have selected them in the first place.
  • The style editor offers the page's own design tokens (Pro). Each value row gets a token picker listing the custom properties the page declares, semantic names first. Picking one applies var(--space-6) rather than the 24px it happens to resolve to — so the page shows the real value and the exported change list names the token, with no mapping table in between. Editing values stays free; reading a team's vocabulary and naming it in the handoff is the design-system layer. Gated in the background broker, not the panel, and the raw pro_required sentinel never reaches the UI — it becomes a short note explaining what Pro adds.
  • ⌘Z / ⇧⌘Z now work while the panel has focus. The page-side listener never hears a keypress made in the panel, and the panel is where the editing happens — the chord is relayed to the content script.
  • Nudge has a remove mode — point at a block and click it away. Modelled on Safari's "Hide distracting items": toggle ✕ Remove in the Nudge pill, hover tints the block a click would take, and it fades out. The targeting is the whole feature — pointing at a paragraph gets you the card it sits in, not the paragraph, because what you want to remove is an item rather than the text inside one. ↑/↓ widen or narrow the target before you commit, which Safari doesn't offer, and the adjustment carries to the next element as an offset. Esc leaves the sub-mode and stays in Nudge, so the adjustments made so far survive. Still preview-only: undo restores the element at its original index, Clear all brings everything back, and a reload resets the page.
  • The Nudge pill is now visible from the moment the mode starts, reading "Drag to move" at rest. It used to appear only once something had been changed, which hid the undo, clear and remove controls behind having already done the thing they control.
  • A themeable Remove target colour joins the overlay style editor alongside the other roles.

Changed

  • The Pro surfaces have tests for the first time. The QA report export, the Figma comparison's summary grouping, and the Figma URL parser were all shipped and sold with nothing covering them. 27 tests now do, including two privacy-policy commitments that had only ever been verified by eye: the exported report issues no network request when opened, and carries no credential or account email.
  • Nudge's remove-target policy moved to shared/dom/removeTarget.ts and is unit-tested for the first time. Measurement stays with the overlay; only the decision moved. That decision took three attempts against a live page and could previously only be checked by driving a browser — as plain numbers it is checked in milliseconds, and the tests encode the exact cases that broke it: a paragraph inside a card, a single-child <div class=card> wrapper, and a page-wide element with no peers.
  • The overlay's chrome builders moved to nudgeChrome.ts — the part that takes values and returns DOM, with no mode state to reason about.

Fixed

  • The remove target could fall back to the page-wide wrapper it had just rejected. The last-resort branch returned the last element in the chain rather than the last one actually considered, so on a page where nothing looked like an item a click could have taken the whole layout. Found by the new tests, not in use.
  • Closing the command palette gives focus back. Esc dropped focus on <body>, so a keyboard user had to tab from the top of the panel again — the palette is meant to be the shortcut, not a detour. It now returns focus to whatever had it when the palette opened.
  • Three contrast failures in Loupe's own UI, found by the above: the dim text token was 4.07:1 on dark and 3.45:1 on light against the 4.5:1 the product itself demands, and white on the brand violet was 4.35:1. All three now pass AA. The violet moved only as far as it had to; it is a background token everywhere it is used, so nothing that was readable got worse.
  • Nudge's crosshair readout no longer contradicts the remove highlight. The rulers layer tracks whatever is under the pointer, so it sat beside a label reading 293 × 225 and announced 247 × 99 — the paragraph inside the card. It's suppressed while removing, along with the inspect engine's own hover highlight.

1.0.0 — 2026-10-02

The launch release. No functional change from 0.11.0 — the version number

is the point: Loupe is feature-complete for a public launch, and 1.0.0 is the

build the launch-day assets and outreach point at. What it carries, in one

place: inspect with a true box model and per-side spacing, element-to-element

measurement, layout grid and rulers, colour picker with WCAG contrast, xray and

find, Tailwind xray, device-emulated responsive preview, a page inventory

(fonts, colours, layout, assets, a11y), and Nudge — move, snap, resize,

group-move, duplicate and remove elements on the live page, then hand the whole

change list to a developer or a coding agent. Pro adds Figma design-vs-DOM

comparison with AI explanations, the a11y audit, breakpoint batch compare, and

the QA report export; teams get offline org licences bound to their own design

system profiles.

Refreshed for launch: store screenshots 01, 02, 03, 05 and 06 re-shot against

this build (01 now shows the DevTools-arrangement box model and working syntax

highlighting, neither of which existed when the old set was taken), and the

grid shot no longer buries the page under a half-opacity wash.

0.11.0 — 2026-10-02

Added

  • Nudge can duplicate and remove elements. ⌘C/⌘V inserts a copy of the selected element right after the original and selects the copy, so the next drag or arrow key positions it; ⌘X/⌘⌫ takes an element out. It answers the layout question Nudge exists for — what this looks like with three cards instead of two, or without the promo block — and stays inside the same preview model: one undo per change, Clear all reverts the lot, and everything resets on reload. Copies never carry the source's id (a second #foo silently retargets the page's own CSS and scripts), get no ghost outline (there is no position they came from), and are marked + copy on the page and in Checks → Nudges. The AI handoff asks for a real second instance — a repeated component, another array entry — rather than copied markup, and ⌘C/⌘X stand aside whenever text is selected, where the browser's own copy is what you meant.
  • Nudge moves a group. Shift+click adds elements to the selection (and Shift+click again removes them); a drag or an arrow key then moves the whole set by one shared delta, so internal spacing is preserved. The pill reads N selected · M adjusted, every member carries its own ring so the set is visible rather than remembered, and because the history already stored one op per gesture as a list of entries, a single ⌘Z steps the entire group back. A plain press outside the group abandons it, so a stale selection can't move elements the user had stopped thinking about. The move is reported once for the whole set (Δ +33, -21px · 2 elements) rather than stamping the same figure on every member; per-element badges keep only what is genuinely per-element, a resize or a text edit.
  • Nudge can resize, not just move. The selected element gets eight drag handles; the Δ badge reports the new size, the Checks list shows it, and the AI handoff prompt asks for a real size change rather than an inline pin. Resizing reflows the page — unlike a move, which uses translate specifically because it doesn't — so from the first resize onward every ghost is drawn from a snapshot of where things sat beforehand, instead of being derived from current positions. Without that, a neighbour pushed by the reflow would have its ghost drawn somewhere it never was.
  • Nudge snaps to the elements around it. Dragging now aligns to nearby elements' edges and centres when within 6px, with a guide drawn through whatever matched — so "line this up with the card next to it" is exact instead of eyeballed. Each axis resolves independently, so an element can snap horizontally while staying free vertically. Hold Alt to suspend snapping when the offset is deliberate. The threshold and the coarse arrow-key step (Shift+arrow, 10px) are both configurable.

Fixed

  • A node that leaves the document and comes back keeps its id. resolveNodeId prunes its forward entry whenever a node is detached, and registerNode then handed the same id back out without re-arming it — so the id could never resolve again. Nudge's remove-then-undo hit this (the panel's "Put this element back" answered ok and did nothing), and so would any framework that re-parents a subtree.
  • Nudge badges no longer hide under the inspector's label. They were drawn at each element's top-left, which is where the inspect engine — always on under Nudge — puts its tag label, so the badge underneath was unreadable. They now hang off the top-right, the one corner the inspector leaves free (its size chip takes bottom-left).
  • Shift+click along a selected card's edge joins the group instead of resizing it. The resize handles sit on top of the selected element's own edges and were checked before the selection modifier, so a Shift+click near an edge started a resize — the element the user meant to add never joined. Shift now outranks the handles, and on a handle it resolves to the element the handles belong to.
  • Clicking in Nudge no longer freezes the hover highlight. Nudge runs the inspect engine as a passenger, and both register capture-phase click listeners — so the inspector's fired first and pinned the selection, turning a click that meant "pick this up to drag" into a lock that lasted the rest of the session, complete with a · locked · Esc badge in a mode where Esc exits. The lock stays where it was asked for, in Inspect and Measure.
  • Screenshots taken while nudging now show the move. The annotated capture hid Loupe's nudge overlay along with its other chrome, so the shot showed the element in its new position with no ghost and no Δ badge — nothing indicating it had moved at all. The ghost and badge are kept; the interactive control pill is still excluded, reusing the repaint the existing nudge screenshot path already does, and restored afterwards so the capture no longer silently removes undo/redo/clear-all.
  • An annotated capture no longer widens to the whole page. The nudge overlay is a full-viewport container, and counting it as an annotation bound expanded the crop to everything on screen. Full-bleed containers are ignored when sizing the crop.

0.10.0 — 2026-10-01

Added

  • Clicking an element locks the inspection to it. The highlight used to follow the pointer unconditionally, so moving toward the panel or the dock walked the selection onto whatever you crossed on the way — and the buttons you were reaching for then acted on the wrong element. A click now pins it: the label reads · locked · Esc, roaming leaves it alone, Esc unlocks and hover preview resumes, a second Esc exits the mode, and clicking another element locks onto that one instead.

Fixed

  • Wrapping in the Code block is a toggle, remembered across sessions. Wrapped by default so nothing is ever hidden; switch it off to get one line per declaration with horizontal scrolling, which reads better when you are scanning a column of values. The button shows which mode is active rather than leaving you to infer it.
  • The Code block wraps, indents, and has one copy button instead of two. Long selectors (utility-class stacks run past 60 characters) used to push the opening brace off-screen with no sign the line continued — it scrolled horizontally and you had to find that out. It wraps now, declarations are indented inside the braces, and the copy affordance moved off the header, where it sat beside the Computed / Declared / Tokens switcher wearing the same pill and read as a fourth view. It lives on the code block itself, over the thing it copies — and is a real <button> with an accessible name, keyboard focus and copied/failed states, where it had been a bare <svg> with an unhandled clipboard promise.
  • The test browser is pinned. playwright was on a caret range that resolved to a Chromium revision which segfaults inside chrome.tabs.captureVisibleTab — one screenshot per run crashed the browser about half the time, two crashed it every time, and the back half of the smoke suite became unverifiable. Pinned to the exact revision that doesn't (dev tooling only; nothing ships to users). The suite goes from "usually incomplete" to 53/53 repeatedly.
  • The box model's spec rows copy real CSS. They used to put 16 · 16 · 16 · 16 on the clipboard — not valid CSS, no property name, and a middot for a separator. They now copy a declaration collapsed the way you would write it by hand: padding: 16px;, margin: 12px 0;, border-width: 1px 2px 1px;, with bare 0 for zero. The tooltip shows exactly what you will get.
  • Esc clears the "locked" badge immediately. Unlocking flipped the state but never repainted, and the overlay only repaints when the hovered element changes — so the badge kept reading · locked · Esc after the lock was gone, surviving not just the keypress but every mouse movement within the same element. The one thing telling you the state said the opposite of the truth.
  • Box-model region hover works in both directions. Moving inward — margin → border → padding → content — highlighted each region correctly, but moving back out left the inner one stuck: the rings nest, and mouseenter does not re-fire for an ancestor the pointer is already inside, so leaving content never told padding it was active again. Leaving a region now hands the highlight back to its parent. Leaving the diagram entirely also clears the page's last-hovered region, which the panel falls back to and which could only otherwise be cleared by a page mousemove that never comes while the pointer is in the panel.
  • The selector label no longer covers a spacing value. isChip() only counted an obstacle wider than 16px and a single-digit value chip renders at ~14px, so every spacing number was invisible to the chip placer and the label sat on top of one. The label is also shorter on the page now — tag plus one qualifier (div.z-dropdown), since the identifying part of a selector is at the front and the tail of a utility stack made the label wider than the element it points at. The full selector is unchanged in the panel, in Copy and in exported reports. It is placed above the whole margin box too, rather than a few pixels above the border edge where the margin's own value sits.
  • Spacing values stay inside their own box. A band too thin to hold its number displaces the chip — padding inward, margin outward. Both used to displace outward, which put the padding value in the margin band, stacked two chips on one spot, and left the label nowhere to go but on top of the element's content.
  • Syntax highlighting in the Code block works for the first time. Shiki has been bundled and fully wired since 0.8.0 and had never once rendered: its oniguruma engine needs WebAssembly, MV3 extension pages run under script-src 'self' with no wasm-unsafe-eval, every highlight threw, and the catch swallowed it — so the block just looked like plain text by design. Switched to shiki's JavaScript regex engine: no CSP relaxation to justify at review, and the wasm payload leaves the bundle. The fallback now warns instead of failing quietly.
  • The Code block shows the whole CSS rule, selector and braces included, which is both what the Copy button has always produced and what the grammar needs for context — without the braces, some property names highlighted and others didn't.
  • Computed hides inert browser defaults. A typical element listed top/right/bottom/left: auto, position: static, z-index: auto, opacity: 1, flex: 0 1 auto and overflow: visible — nine lines out of twenty saying nothing. Gone, per property rather than by blanket rule: the old filter dropped any 0px, which silently hid top: 0.
  • Declared no longer reports values that lost. It walked top-level rules only, so everything inside @media was invisible — most of the interesting CSS on a responsive site — and matching rules overwrote each other in source order, so a weak rule later in the sheet beat the specific one that actually applies. Now it descends into @media (only while the condition holds), @supports and @layer, and resolves by !important, then specificity, then source order, with inline styles last.
  • The Tokens empty state pointed at a tab that doesn't exist — "the DS tab", which became Checks in 0.8.9.
  • The panel's icon buttons say what they do. Icon-only chips relied on the native title, which waits about a second and renders unstyled OS chrome — so a row of three icons read as unlabelled. Panel chips now show an instant, themed tooltip on hover and on keyboard focus.
  • Spacing figures line up in columns under top / right / bottom / left headers, instead of running together as 2 · 0 · 0 · 0 with the legend stranded in a corner. 120 · 8 · 8 · 8 and 2 · 0 · 0 · 0 used to start at different offsets — the kind of misalignment this tool exists to catch.
  • A zero-width border no longer reports a style. border computes to 0px solid rgb(128, 128, 128) even when there is no border, which showed a default colour nobody chose as though it were a design decision.
  • Element dimensions round consistently — the header read 842.000 × 52, three decimals against zero.
  • Every non-zero spacing value is labelled on the page. A band thinner than its own label used to be left unlabelled — which silently swallowed a plain padding: 12px, one of the most common values in CSS. Chips that cannot fit inside their band are now placed just outside it, so they still point at the right strip without covering it.

Changed

  • The box model follows the Chrome DevTools arrangement. Each ring names itself from inside its own band and carries its four values on its four sides — zeros included, because a gap where a number should be is not information — with the element's content dimensions at the centre. Rings are a uniform thickness: an earlier build sized them to the real values, which read well until the labels moved inside, where a ring sized to a 1px border could not hold its own text. Hovering any region — margin, border, padding or content — outlines that exact region of the element on the page, and pointing at a padding band on the page lights the matching ring in the panel. Below the diagram, the aligned top/right/bottom/left table stays for scanning and click-to-copy, and border style, radius and shadow are listed under it. The centre cell now reports the content box rather than the border box, which is what it has always been drawing.
  • Copy the annotated image straight to the clipboard. A new action in the Element tab puts the whole thing — element, spacing annotations and box-model card — on the clipboard as a PNG, so it pastes into CleanShot's "Annotate from clipboard", Figma, Slack or a ticket without a detour through the downloads folder. Deliberately app-agnostic rather than wired to one screenshot tool: nothing to detect, nothing to break when it isn't installed, and it works the same on every platform.
  • The annotated screenshot now carries the box model. The exported PNG composites the full spec card — nested margin / border / padding rings with all their values and the content dimensions — beneath the element and its on-page annotations, so the shot is a complete handoff instead of something you have to pair with a panel to read. It is drawn, not cropped from the panel: that way T works with the panel closed, the output never depends on panel scroll position, and no panel chrome creeps into frame. Loupe's own "locked" badge is stripped from captures for the same reason.
  • Screenshot an element with its measurements, T. A new dock button and the T shortcut capture whatever you're pointing at and save a PNG with the spacing bands, their values, the selector label and the size badge baked in — while keeping Loupe's own dock and panel out of frame. The crop grows to fit the annotations, so the margin band and chips aren't sliced off. The Element tab now offers both captures: the component on its own, or annotated.

0.9.0 — 2026-09-21

Fixed

  • Xray no longer outlines Loupe's own UI, and — the bigger one — the Page inventory no longer records Loupe's injected styles as the page's design: with Xray active, the entire outlines group used to be Loupe's own overlay palette (Find highlights polluted it the same way). The inventory now disables Loupe's injected stylesheets for the duration of the scan — and the same guard protects the DS lint, dark-mode diff and accessibility-contrast audits, which sampled the same polluted styles.
  • Layout-grid settings survive a browser restart. Colour, opacity, columns and margins lived only in session storage and silently reset; they now mirror to durable prefs like the dock position.
  • The Element tab's "CSS" copy button confirms ("Copied"/"Failed") instead of giving no feedback at all.
  • Tailwind Xray says so when a page has no utilities instead of entering silently with nothing painted — the mode looked dead on non-Tailwind sites.
  • Find highlights follow your overlay-style colours (Settings → Overlay appearance) instead of staying hardcoded red/amber, and the match counter no longer counts elements a SPA rerender removed.
  • The colour picker can no longer show stale colours: if the post-scroll recapture fails (rate limit, window blur), the old snapshot is dropped and the bubble stays hidden until a fresh capture lands — previously it confidently sampled the pre-scroll screenshot at the new position.
  • Find also stops scanning the document twice per keystroke (the dock input and the store sync both triggered the same search).

0.8.9 — 2026-09-20

Fixed

  • "Copy AI prompt" actually copies on the in-page panel. The panel iframe lacked the clipboard-write permission policy, so every copy button silently failed there (the native side panel was fine) — and the failure was swallowed, so the button just looked dead. The iframe now grants clipboard-write, a legacy fallback covers the rest, failures say "Copy failed", and success reads "Copied — paste into your agent". The button is also renamed from "AI fix prompt" to Copy AI prompt with a tooltip clarifying no API key is needed — it writes a prompt for YOUR agent, it doesn't call an API.
  • The AI explainer now says why it isn't working. Without an API key the "Explain with Claude" feature was simply invisible on FixCards — it now shows "AI explanations need your Anthropic API key" with an Add-API-key button that opens the key form and scrolls it into view. Key-rejection errors say so plainly with the same shortcut, and the raw pro_required sentinel now reads "AI explanations are part of Loupe Pro."

Changed

  • Design-system profiles import in one pick, right from Checks. The Components, Lint and Dark-diff checks now offer "Import profile JSON" directly (importing also binds the profile to the current site), with a link to the authoring guide — no trip through Settings. Once a profile is bound, each check shows which profile is active with an Update button that takes a replacement JSON in one pick. The full manager (URL fetch, paste, multiple profiles, unbind/delete) stays in Settings.

0.8.7 — 2026-09-19

  • Measurement lines got the classic dimension-line look. Distance lines now end in double-headed arrows, and the value sits in a light pill with a cyan border and cyan text — legible on any page background — instead of a solid colour block. Sans-serif with tabular numerals.

0.8.5 — 2026-09-18 (uploaded, superseded by 0.8.6 before publish)

0.8.4 — 2026-09-18

Changed

  • Inspect, Measure and Rulers are separate modes again. The 0.8.3 unification put every annotation on screen at once — selector label, size badge, X/Y/W/H readout and distance chips all crowding the same corner on dense pages. Each mode now shows only its own annotations: Inspect (I) hover-highlights and selects, Measure (D) does anchor-and-hover distances, Rulers (R) does bars, crosshair and the X/Y/W/H readout. Measure and Rulers get their dock buttons back.
  • R inside Rulers mode hides the bars — crosshair, guides and readout stay, so nothing covers the page's top-left corner; a third press exits.

Fixed

  • Unpacked builds are now labeled "(dev)" in chrome://extensions. The store install and a local dist/ load otherwise show the same name, icon and (between releases) version, and running the store copy while iterating locally produced a day of ghost bug reports. pnpm package builds the clean-named release; plain pnpm build marks itself dev.
  • Annotations no longer stack on top of each other. Every chip goes through one shared placer: it takes the first free anchor, dodges chips already on screen and the ruler gutter, and walks downward when a tight cluster leaves no free anchor. Long selector labels — Tailwind arbitrary variants like [&:has([role=checkbox])]:pr-0 — are truncated instead of banner-width, and the X/Y/W/H readout sits below the element.
  • Ruler bars no longer hide the page underneath them. They now fade from a readable tint at the outer edge to nearly clear at the inner edge, with haloed ticks and numbers, instead of painting an opaque strip over content.

Changed

  • Responsive mode reworked. The device controls move from a strip injected into the previewed page — which could never be wider than the phone it was previewing, and covered the site's own header — into a dock popover with a device picker, size fields, rotate, and a zoom control. The preview now scales to fit the window by default (Fit / 50% / 100% / 150%), so a 390px phone fills the space instead of sitting in a black corner; the page still computes at its real CSS width, so breakpoints stay exact. The dock auto-compacts when the previewed viewport is too narrow for it, keeping the responsive control reachable. The area beside the preview is now a neutral stage colour that follows your theme, and a Fit window to device button resizes the browser window around the preview to close the gap entirely (exiting restores your previous window bounds).
